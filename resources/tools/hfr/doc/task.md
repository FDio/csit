# Hands-Free Releasing - Documentation

## Goal

Document the project `Hands-Free Releasing`.

Create accurate, useful documentation for this codebase so a new engineer can
understand, run, modify, test, and operate the project.

## Audience

A backend/full-stack engineer joining the project for the first time.

## Workflow

1. First inspect the repository structure, existing documentation, package/build
   files, main entry points, configuration files, source modules, tests,
   scripts, deployment files, and CI files.
2. Do not edit `README.md` file until you understand the project structure.
3. If documentation in `README.md` already exists, update it instead of
   duplicating it.
4. If something cannot be confirmed from the code, ask instead of guessing.

## Please create or update documentation covering

1. Project overview
   - What the project does.
   - Main use cases.
   - Important runtime components.
   - Tech stack.

2. Architecture
   - High-level architecture.
   - Main modules/packages/services and their responsibilities.
   - Request flow or job flow.
   - External systems and dependencies.
   - Add Mermaid diagrams where helpful.

3. Setup and local development
   - Required tools and versions.
   - Environment variables.
   - Install commands.
   - How to run locally.
   - Common local-development workflows.

4. APIs / interfaces
   - HTTP APIs, CLI commands, jobs, workers, events, or public functions.
   - Inputs, outputs, error behavior, and examples where discoverable from code.

5. Data model and storage
   - Main entities, schemas, database tables, files, queues, caches, or external
     storage.
   - Migrations or schema management.
   - Important data-flow notes.

6. Configuration
   - Environment variables.
   - Config files.
   - Feature flags.
   - Secrets handling.
   - Default values where visible in code.

7. Build and deployment
   - Build commands.
   - CI/CD flow.
   - Deployment artifacts.
   - Runtime process model.
   - Operational dependencies.

8. Operations and troubleshooting
   - Logs.
   - Health checks.
   - Metrics.
   - Common failure modes.
   - Useful debugging commands.

## Output files

- `README.md`
- diagrams

## Rules

- The script `process_reports.py` is a separate script and processes the .csv
  file generated by HFR. Document it separately.
- Do not change application source code.
- Do not change documentation outside `README.md`.
- Write the diagrams do `./doc/img/`.
- Do not refactor anything.
- Do not add new dependencies.
- Prefer facts from source code over assumptions.
- Include file references for important claims.
- Keep docs concise but complete.
- Use Markdown.
- Use an editable `.drawio` source and an exported `.svg` for diagrams.
- If a file path or behavior is uncertain, say so clearly.
- After writing the docs, run a quick consistency check by re-reading the
  generated files and comparing them against the codebase.
- Finish with a short summary of created/updated files and any remaining
  uncertainties.
